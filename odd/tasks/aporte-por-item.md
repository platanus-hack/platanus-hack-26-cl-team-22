# Aporte por ítem: licitaciones y proyectos SEIA

Objective: expose, per comuna, the individual tenders (ChileCompra) and SEIA projects with the exact contribution each one makes to the model/indicators. Data only; UI goes to a GitHub issue for GdCastellano.
Branch: `feat/aporte-por-item`. Delivery: ask-on-risk. Test runner: `make test` (pytest) + `make lint` (ruff check).

## Specs

- **S1** Per-tender detail is persisted: a CSV under `data/licitaciones/` with one row per deduplicated `(codigo_comuna, codigo_externo)` 2024 RM municipal tender, keeping the tender name (`Nombre`), its state (awarded / failed / open), sector, `monto_estimado`, `monto_adjudicado`, `numero_oferentes`. Generated by `datos.licitaciones.fetch_licitaciones` (including `--solo-locales` from the local ZIPs); the existing aggregate CSVs stay byte-identical.
- **S2** Each tender's exact contribution to the municipal credibility uses the simulation's own data: the same prior (`SECURITY_CREDIBILITY`, `experiments/simular.py:95`), the same `estimate_commune_credibility` (`core/licitaciones.py:117`, `max_effective_n`), and the target comunas and credibility read from `viz/datos/simulacion.json` (`politicas[].credibilidad_por_comuna`). Contribution = leave-one-out change of the credibility posterior mean (closed tenders only; open tenders contribute exactly 0). The builder asserts that the recomputed mean equals `credibilidad_por_comuna.media` for every target comuna and fails otherwise. Comunas whose credibility does not enter the model are flagged (e.g. `afecta_modelo: false`) — their tenders are listed as context with model contribution 0, never an invented weight. No change to model outputs.
- **S3** Output JSON for the viz next to `simulacion.json` (`viz/datos/`), compact, one entry per comuna with its tenders, the comuna's counts, credibility and the per-tender contribution; a Makefile target regenerates it. `simulacion.json` / `simulacion-15.json` are not modified.
- **S4** SEIA per-project detail: `datos/viz/build_inversion.py` also emits, per comuna, the list of projects that make up `inversion_evaluada` (same rule: "Aprobado", `fecha_presentacion >= 2015-01-01`, multi-comuna counted once per comuna) with `expediente_id`, `nombre`, `titular`, `tipologia`/`descripcion_tipologia`, `inversion_musd`, `fecha_presentacion`, `url_ficha`, and contribution `+1` to the count. Invariant: list length == `inversion_evaluada` for every comuna. Existing `inversion.json` content stays identical.
- **S5** A GitHub issue assigned to GdCastellano describes the UI: on selecting a comuna, list its tenders and SEIA projects and show each one's contribution, using the files/schemas of S3 and S4, with the honest caveats (2 distinct tender values per comuna, only target comunas affect the model, a single tender's effect on crime is below Monte Carlo resolution).
